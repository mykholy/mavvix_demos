# Mavvix Demo Factory V2 — Production-grade Gemini Flash Implementation Kit

**تاريخ المراجعة:** 19 نوفمبر 2026 • **الغرض:** إعطاء Gemini Flash تعليمات هندسية وبصرية ومحتوى متخصص لتحويل 8 مواقع Demo إلى تجارب حقيقية قابلة للتصفح والإدارة والاختبار — **وليست Mockups أو صورًا ثابتة**.

## إيه الجديد عن ZIP القديم؟
راجعت الحزمة القديمة كاملة (43 ملفًا). وجدت ضعفًا واضحًا في عمق بعض القطاعات؛ ديمو المطاعم والأكاديميات كان كل منهما وصفًا مختصرًا، وSQLite كان جدول طلبات عام، ولم تكن هناك مواصفات CMS فعلية. V2 تحل ذلك بتفصيل كل Route وكل رحلة، DB من 28 جدولًا، جميع القطاعات الثمانية إلزامية، Content Studio Admin وعقد اختبار لكل ديمو. بيانات الـ Seed بداية هيكلية، وGemini مسؤول عن إنتاج المحتوى الطويل والميديا القانونية والتأكد منها، فلا تعتبر تلك الأجزاء منجزة لمجرد وجود JSON.

## الناتج المطلوب من Gemini
- **8 مواقع تفاعلية كاملة**: مقاولات، مصانع/تصدير، عقارات، أسنان، متجر، بورتفوليو، مطاعم، أكاديمية. لكل منها 10+ Route Patterns مع صفحات تفاصيل كثيرة وعربي/إنجليزي وهوية خاصة.
- **SQLite/Node حقيقي:** مصدر بيانات واحد، طلبات وعربات وعروض أسعار وتجارب حجز وQuiz Progress محلية ذات حالة حقيقية، بدون إرسال أي عمليات خارجية.
- **لوحة إدارة محتوى فعلية محمية:** إدارة الصفحات والأقسام والمقالات والصور والهوية وبيانات كل قطاع والطلبات التجريبية، مع Draft/Publish/Rollback.
- **Showcase تجاري لـ Mavvix:** يعرض فقط الديموهات المكتملة، بصور Screenshots من التطبيق المشغل فعليًا، CTA للعميل للتواصل مع Mavvix.
- **QA:** مئات معايير التحقق تشمل URLs، المحتوى، الفلاتر، السلة، الرسائل، الـ Admin، الداتا، RTL/EN، Responsive، صور وإعلانات، مراجعة الادعاءات.

## طريقة التشغيل
1. فك ZIP داخل مجلد مشروع جديد أو Repository الخاص بالمشروع، في Gemini Flash ضمن بيئة تسمح بقراءة/كتابة ملفات وتشغيل Terminal.
2. أرسل محتوى `00_AGENT/START_WITH_THIS_PROMPT.txt` حرفيًا. البرومبت الرئيسي `00_AGENT/MASTER_IMPLEMENTATION_PROMPT.md` وفيه ترتيب القراءة والتنفيذ. 
3. أو اكتب لـ Gemini: "اقرأ ملفات الحزمة كلها وابدأ تنفيذ المشروع من الملفات فعليًا؛ لا تتوقف عند خطة أو Homepage".
4. Gemini ينفّذ Foundation وContent Studio أولًا، ثم المواقع بالترتيب من 01 إلى 08، وكل موقع لا يُعد كاملًا إلا بعد Route coverage + 3 journeys + SQLite + Admin + Tests + Screenshots.
5. لو جلسة Gemini انتهت، استخدم `00_AGENT/RESUME_PROMPT.txt` أو برومبت التخصص داخل `00_AGENT/SECTOR_PROMPTS/`. «بدون توقف» مقصود بها متابعة الخطوات تلقائيًا داخل حدود الجلسة، وليس ضمان تشغيل مستمر خارجها.
6. نقدر نعرض أول 3 ديموهات بعد اختبارها ونسميها **معاينات مرحلية**. لكن لا نقول المشروع مكتمل إلا بعد نجاح الثمانية.

## ملفات أساسية
- `04_DEMOS/01...08.md`: كل مجال بمسارات فعلية، شاشات مفصلة، UI، بيانات، 3 رحلات، Admin، QA.
- `04_DEMOS/BLUEPRINTS/*.json`: Blueprint قابل للقراءة الآلية لكل تخصص.
- `02_DESIGN/FIRST_FOLD_AND_STORYTELLING_V2.md`: الـ Hooks والتصاميم الفريدة لأول شاشة والتسلسل البصري.
- `05_ENGINEERING/sqlite_schema.sql`: قاعدة البيانات القياسية التي اختُبر Syntax الخاص بها.
- `05_ENGINEERING/ARCHITECTURE_V2.md`, `ADMIN_STUDIO_REQUIREMENTS.md`, `SQLITE_SEED_AND_CONSISTENCY.md`: التنفيذ والتشغيل الفعلي.
- `05_ENGINEERING/SEED_DATA.json`: بيانات وسيناريوهات بداية لجميع المجالات، بحاجة لإكمال كتابة المحتوى والصور.
- `06_QA/MATRICES/ACCEPTANCE_TESTS_V2.csv`: حالات تحقق تفصيلية لكل القطاعات.
- `07_MARKETING/SHOWCASE_SALES_EXPERIENCE_V2.md`: تحويل التجربة لعميل محتمل.
- `08_BRAND/official_assets`: هوية Mavvix الأصلية، يجب عدم تغييرها.

## الحقيقة المهمة
**هذا ZIP ليس مشاريع React منفذة.** هو حزمة Implementation Specifications + Prompt + Source Assets + Seed Contracts + QA تم إعدادها لإرسالها إلى Gemini لإنشاء تلك المشاريع. لا يمكن ضمان حصول المستخدم على مواقع كاملة من Gemini بدون قدرة بيئة Gemini على تشغيل الكود والاختبارات ومراجعة الميديا، ولا من جلسة نصية واحدة بالضرورة.

## حدود الديمو الأخلاقية والتقنية
كل الشركات والأسماء والمنتجات والعقارات والأطباء في الديموهات **خيالية وتجريبية**. مع ذلك تجربة الاستخدام والعمليات الداخلية تعمل محليًا بالفعل. أي إرسال طلب أو طلب زيارة/موعد أو شراء يشرح أنه simulated ولا ينشئ معاملة خارجية، ولا يستخدم الدفع الحقيقي أو بيانات طبية أو بيانات اعتماد حسابات العملاء. يظل إعلان Mavvix يعرض هذه المواقع باسم "Concept Websites" وليس "مشاريع عملاء منفذة".
