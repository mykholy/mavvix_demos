## Journey 1: Learning Discovery to Lesson Progress & Scored Quiz Evaluation

### Objective
Verify that a prospective learner can explore the curriculum catalog, filter by track, open a course syllabus, launch an interactive preview lesson, review substantive 400+ words technical material, mark the lesson as completed (persisting in SQLite), and complete an assessment quiz with deterministic scoring (3/4 = 75%).

### Step-by-Step Execution & Results
1. **Visit Academy Home (`/preview/academy`):**
   - User reviews the 4 career tracks: Data Science & AI, Software Engineering & Cloud, UX Architecture & Design Systems, and Growth Marketing & Funnels.
   - User clicks "Explore All 12 Curricula" leading to `/preview/academy/courses`.
2. **Filter & Select Course (`/preview/academy/courses`):**
   - User filters by track `data`. Catalog updates live to display 3 data curricula.
   - User clicks `course-01` ("Foundations of Data Engineering & SQL Warehousing").
3. **Inspect Syllabus Dossier (`/preview/academy/courses/course-01`):**
   - User inspects syllabus accordion tree showing 6 modules/lessons.
   - User notices `lesson-01-01` ("Data Architecture Invariants & Schema Design") has a "Free Preview ⚡" badge.
   - User clicks "Launch Preview Lesson" leading to `/preview/academy/learn/course-01/lesson-01-01`.
4. **Lesson Study & Progress Persistence (`/preview/academy/learn/course-01/lesson-01-01`):**
   - User reviews simulated video player substitute and reads the substantive 400+ words technical transcript covering architectural invariants, real-world failure modes, and practical lab directives.
   - User clicks "Mark Lesson Completed".
   - Client sends POST to `/api/demo/academy/progress` with `{ itemType: 'lesson', itemId: 'lesson-01-01', status: 'completed' }`.
   - SQLite writes record to `demo_guest_progress` with `(guest_token_hash, lesson_id, completed=1)`.
   - UI displays immediate confirmation: "✓ تم حفظ إتمام الدرس بنجاح في قاعدة بيانات SQLite محليًا."
5. **Scored Quiz Assessment (`/preview/academy/quiz/lesson-01-01`):**
   - User navigates to the quiz. 4 multiple-choice questions are presented.
   - User answers Questions 1, 2, and 4 correctly, and Question 3 incorrectly.
   - User clicks "Submit for Scored Evaluation".
   - Evaluation engine calculates score: `3 / 4 * 100 = 75%`.
   - Score banner renders with green success styling: "75% (3 / 4 إجابات صحيحة) — تهانينا! لقد حققت نسبة النجاح المطلوبة (>=75%)".
   - Score is persisted to SQLite `demo_guest_progress` (`quiz_score = 75`).
   - Detailed per-question review shows green badges for correct answers, red for wrong, and technical rationale boxes explaining each answer.

## Journey 3: Edge Case & Validation Handling

### Objective
Verify that the academy platform handles client and server validation errors gracefully, blocks incomplete quiz submissions, rejects invalid course choices, and displays transparent non-accreditation disclosures.

### Step-by-Step Execution & Results
1. **Incomplete Quiz Submission Attempt:**
   - In `/preview/academy/quiz/lesson-01-01`, user selects only 2 of the 4 questions and clicks "Submit for Scored Evaluation".
   - Client-side validation triggers: form submission is halted.
   - Red alert displays: *"يرجى الإجابة عن كافة الأسئلة قبل التقييم. لديك (2) أسئلة متبقية."*
   - Unanswered questions are highlighted with red border rings.
2. **Invalid Course Selection Rejection (Server 422):**
   - In `/preview/academy/enrollment-interest`, user selects the test option `[Invalid Choice - Test Edge-Case Rejection]`.
   - Server endpoint `/api/demo/academy` intercepts `payload.courseSlug === 'invalid-choice'`.
   - Returns HTTP 422 with JSON `{ error: 'Invalid course selection...', code: 'INVALID_COURSE_SELECTION' }`.
   - Form displays error banner without crashing.
3. **Missing Applicant Details Rejection (Server 422):**
   - Submitting with an empty applicant name triggers server validation error: `INVALID_GUEST_NAME`.
   - Submitting without email and phone triggers: `INVALID_CONTACT_INFO`.
4. **Non-Preview Lesson Locking:**
   - For non-preview lessons (e.g. `lesson-01-03`), the syllabus renders a subtle locked state: `🔒 Enrolled only / متاح بعد تأكيد الالتحاق`.
   - Lesson outline displays clean locked indicator and directs user to register enrollment interest.
