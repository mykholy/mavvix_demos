# Exact definition of DONE, PARTIAL, BLOCKED

## DONE requires ALL
1. Full route list for vertical present and navigable directly in AR and EN.
2. Every major list/detail shows multiple coherent records; primary detail page has decision support and consistent photos, not cloned generic filler.
3. Main 3 journeys from brief function end to end, show real state transitions, appropriate errors, sample receipt and persistence (where specified).
4. SQL content source and admin CRUD/draft/publish/rollback work; edits reflected on public site after publish; unauthorized edits rejected.
5. Mobile screenshot and keyboard/RTL verified. No horizontal overflow at 320 or 390.
6. No dead links, empty modal content, fake transactions, invisible failures, placeholder text, missing image credits.
7. Tests actually run and pass; screenshots from running app saved, no fabricated metrics; acceptance matrix signed.
8. Hero + detail + flow + admin each distinctive and polished; global gallery links live and demo-only disclosure visible.

## PARTIAL when
Some routes built or screenshoted, but core flow/admin/persistence/test incomplete. Public Showcase must not list it as completed.

## BLOCKED when
Unresolved environmental missing persistent disk, no licensed hero imagery, major accessibility bug, broken build, incomplete medical safety review, unverified product data. Declare blocker and next fix.

## Hard stop conditions
Never create fake case study/client reviews to hide lack of proof; never claim an order paid, booking confirmed, medical advice approved or actual leads delivered. Do not publish real customer data. Production site deployment needs independent approval.
